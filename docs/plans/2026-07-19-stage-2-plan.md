# Stage 2 Implementation Plan (bootstrap)

> Created after Stage 1 verticals closed. Do not start implementation until Stage 1 gate evidence is filed.

## Goal

Move from pilot-ready modular monolith to multi-provider production: real channel adapters, durable workflows, DB-backed API repos, WebSocket only if measured, full RAG/eval, and ops maturity.

## Non-goals (still)

- Multi-region active-active
- Custom PSP refund execution beyond Stage 1 stop-on-paid model
- Label purchase / logistics write APIs

## Workstreams

### S2-1 — API persistence
- Wire Nest API to Postgres (`@chai/database` + domain functions)
- Drop in-memory repositories behind feature flag then delete
- Integration e2e against testcontainers from API process

### S2-2 — Provider adapters
- WhatsApp / Meta sandbox adapter behind connector-sdk
- Real calendar (Google/Microsoft) adapter with OAuth store
- Conformance suite must pass before enablement

### S2-3 — Durable automation
- Temporal (or equivalent) for follow-up, payment reconcile, logistics poll
- Replace no-op automation/payment/logistics worker bodies

### S2-4 — Knowledge production
- pgvector hybrid retrieval, chunking pipeline, media-worker S3 path
- Prompt release versioning + eval harness

### S2-5 — Realtime + UI
- Replay cursor retention, multi-tab presence only if needed
- Wire client portal payments/shipments to live APIs (not fixtures)

### S2-6 — Ops
- Canary + kill switches per module
- Automated backup restore drill in CI
- SLO dashboards from otel metrics

## First executable task (when Stage 1 signed off)

**Files:**
- `apps/api/src/database/*`
- Swap `InMemoryConversationRepository` → domain ingest under tenant transaction
- Test: API e2e against integration DB

## Exit criteria

- Zero in-memory repositories in default `NODE_ENV=production`
- One real channel sandbox end-to-end in staging
- Follow-up job survives process restart
- Stage 1 isolation suite still green
